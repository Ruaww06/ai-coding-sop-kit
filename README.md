# AI Coding SOP Kit

**让你的 AI 开发助手有章可循：需求不清先问、改动不越界、验证不造假、连续失败会停手。**

这是可放进项目的纯文档规约包。适用于新项目，也可合并进已有项目；不要求你先懂编程、写完整需求或选择技术栈。AI 会按工作流协助你澄清，但业务取舍和最终验收仍由你确认。

无需安装程序或新增依赖，无需每次手动调用 Skill。**它是行为指引，不是保证 AI 永远遵守的自动门禁。**

## 快速开始：把配置交给你的 AI 助手

### 1. 打开你要开发的项目

在具有文件读写能力的 AI 开发工具中打开项目文件夹，而不是本工具包的仓库。新项目可以是空文件夹。当前工作区不明确时，下面的指令会要求 AI 先向你确认。

### 2. 复制下面整段指令发送给 AI

不需要改路径；默认接入当前项目。AI 需要能下载公开仓库或访问你本地已下载的工具包。

```text
请帮我把 AI Coding SOP Kit 安全地接入当前项目。
来源：https://github.com/Ruaww06/ai-coding-sop-kit

这次只授权接入规约文档，不授权开发业务功能、安装依赖、执行下载的脚本、修改全局配置、提交、推送或部署。

请按以下步骤完成：
1. 确认当前项目的根目录并检查已有规约与同名文件。如果目标不明确，先问我；不要把工具包仓库本身当成目标项目。
2. 获取工具包的文档并审阅。不要直接在项目根目录克隆或覆盖；使用临时/独立目录或已有本地副本。网络不可用时向我要本地来源，不编造已下载。
3. 先检查 docs/sop/ 和 .agents/skills/sop/ 中的每个目标文件，再逐文件接入，不整体替换目录（包含隐藏目录 .agents/）。AGENTS.md 不存在时使用工具包版本；已存在时合并规则和工作流入口，保留项目原有约定。有实质冲突或同名内容无法安全合并时，只暂停受影响部分并请我裁决，不删除或强行覆盖。
4. 将工具包的 LICENSE 另存为 docs/sop/LICENSE，保留来源与 MIT 许可。不要覆盖项目根 LICENSE，不复制工具包的 .git/、README.md 或无关文件。重复接入时只处理必要差异，不生成第二套规则。
5. 根据我当前工具的官方能力和工具包 adapters 说明确认加载方式；不猜命令、不为未证实的兼容性创建额外配置。无需快捷命令也能通过 AGENTS.md 引导读取工作流。
6. 检查入口引用的文件是否存在，确认项目原内容未被误覆盖。只审阅文档，不因配置任务运行项目业务脚本或测试。
7. 报告目标目录、实际新增/修改文件、冲突、核验结果，以及自动加载是否真正验证；无法验证就明确写未验证，不声称已经保证遵守 SOP。

接入后请实际读取 AGENTS.md 和其中引用的工作流，按当前需求与任务判断阶段。尚无业务需求时只说明从需求澄清开始；先结束本次配置，不擅自实现产品。
```

本段指令用于具有项目文件访问能力的开发 Agent。普通网页聊天或不能写文件的助手只能给出指导，不能完成接入；不要向其上传凭证或私密文件。

### 3. 核对配置结果，然后直接说需求

至少确认 AI 报告了：

- 正确的项目目录，以及每个新增/修改文件。
- `AGENTS.md` 中的工作流入口，且引用文件都存在。
- 原项目规约和许可证得到保留，没有业务实现或全局配置改动。
- 工具自动加载哪些已实测、哪些未验证；不是只说“配置成功”。

条件允许时，核对工具记录或文件差异。**文件接入完成 ≠ 自动加载已验证 ≠ SOP 行为已验收。**

之后直接发送真实需求，例如：

```text
我想做一个管理个人笔记的工具，但需求还没想清楚。
请按项目 SOP 先帮我澄清真实使用场景，起草可判定的验收标准。
不要替我确认业务规则，暂时不要写业务代码。
```

空项目不要求先准备代码或测试；不存在的基础明确标为不适用，再由 AI 提出最小初始化方案。确认目标、验收和范围后，可以发送：

```text
上述目标、验收标准和改动范围已确认，授权你在该范围内初始化、实现并验证。
只使用已确认的依赖和操作；没有新的关键歧义或风险时直接继续，不重复索要同一授权。
实际无法完成的验证列为未验证，独立评审和最终验收尚未进行时保持待验收。
```

不必每次调用 `/skill:sop` 或补“遵守 SOP”。换会话后确认工具加载入口；不支持自动加载时说“先读取 AGENTS.md，按其中流程继续”。

## 为什么不是只放一份长提示词？

| 内容 | 作用 |
| --- | --- |
| `AGENTS.md` | 常驻底线与读取入口 |
| `.agents/skills/sop/SKILL.md` | 唯一工作流正文；可直接读取，不依赖 Skill 命令 |
| `docs/sop/workflow.md` | 各阶段出口、停止条件和失败路由 |
| `docs/sop/templates.md` | 需求、任务、验证与交接的按需模板 |
| `docs/sop/original.md` | 完整 SOP v1.0 原文，按需查阅 |
| `docs/sop/adapters/` | 各客户端接入方式与限制 |

工具包不附带脚本、任务 JSON、项目历史、业务代码、客户端全局配置或安装程序。项目验证使用自己的测试、构建、实测和 CI；没有验证基础时由 AI 提出适用方案，不能把缺失当通过。

## 不同工具怎么使用？

| 工具 | 接入方式 |
| --- | --- |
| [Kimi Code](docs/sop/adapters/kimi.md) | 读取 AGENTS.md；支持时可选 `/skill:sop` |
| [Claude Code](docs/sop/adapters/claude-code.md) | 原生 AGENTS.md 有版本与加载条件，不默认添加兼容文件 |
| [DeepSeek Harness](docs/sop/adapters/deepseek-harness.md) | 核对指令和 Skill 插件/组合的加载能力 |
| 其他开发工具 | 显式读取 AGENTS.md 及其工作流，先验证能力 |

不假设所有工具自动识别同一目录。加载 AGENTS.md 也不等于客户端自动加载它引用的全部文件，后续读取仍由 Agent 执行。

## 手动接入 / 网络不可用

下载 [ZIP](https://github.com/Ruaww06/ai-coding-sop-kit/archive/refs/heads/main.zip)，或克隆到项目之外的独立目录：

```sh
git clone https://github.com/Ruaww06/ai-coding-sop-kit.git
```

将以下内容合并进目标项目：

- `docs/sop/` 和 `.agents/skills/sop/`；
- 根 `AGENTS.md`：已有则合并，不覆盖；
- 本包 `LICENSE` → 目标项目 `docs/sop/LICENSE`，不覆盖项目自身许可证。该声明适用于接入的工具包文件，不改变项目业务代码的许可证。

如果同名内容冲突，先备份到项目外并审阅差异，不能整目录覆盖。不要复制 `.git/`。网络不可用时，把本地工具包位置告诉 AI，继续使用上面的配置指令。

## 常见问题

**空项目也能用吗？** 可以。不要求先有技术栈、测试或完整 PRD。先接入文件，再从真实需求澄清开始；不要因为缺基础就伪造“全绿”。

**会影响已有项目吗？** 会增加行为约定，所以必须审阅合并。保留原规约和代码；不强制迁移任务平台、文件格式或测试工具。

**换 AI 或换工具需要重新配置吗？** 同一项目的核心文件继续共用；核对新工具的加载方式，并让新 Agent 恢复当前任务、真实确认来源、失败次数和旧误区，不重写已确认需求。

**如何更新？** 使用新的工具包副本，先比较差异再合并。保留项目定制，不能直接覆盖；本包没有自动升级机制。

**如何撤销？** 根据接入时记录的文件清单和差异，只撤销本次新增内容与合并片段。不要删除整个 AGENTS.md 或文档目录；之后的项目改动必须保留。

**能保证 AI 遵守吗？** 不能。首次接入后观察歧义时是否提问、越界时是否请求授权、未验证是否如实报告、连续失败是否停手。读取、diff 和 runner 证据比 Agent 承诺更可靠。关键审批和最终验收仍需要人。
