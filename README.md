# AI Coding SOP Kit

给编程 Agent 的轻量工程技能：明确问题和授权，先查已有解，在完整影响范围内做最小改动，以真实证据交付。

**SOP 内容 v3.1 · 包版本 3.1.0-beta.2 · Beta 测试版。** 按职责组织五个按需技能与一份共享边界，不沿用旧版的固定文件套装、审批分类或强制分会话流程。旧技能、模板库和重复规则已移除；已有一条人工审批升级与两个原生技能调用观察，更广泛的宿主安装和模型行为仍待验证。

## 一句话交给 Agent

在 Agent 中选中目标项目，发送：

```text
请获取并遵循 https://raw.githubusercontent.com/Ruaww06/ai-coding-sop-kit/refs/heads/main/INSTALL.md，识别当前宿主，将 AI Coding SOP Kit 安装到当前项目；先核对实际版本，遇到冲突询问，不覆盖项目定制，也不自动开始业务开发。
```

该链接跟随公开 main，实际安装以获取到的版本和 commit 为准。固定本版请读取 [v3.1.0-beta.2 安装指南](https://github.com/Ruaww06/ai-coding-sop-kit/blob/v3.1.0-beta.2/INSTALL.md)，并使用同一标签的完整源码。[v3.1.0-beta.1](https://github.com/Ruaww06/ai-coding-sop-kit/releases/tag/v3.1.0-beta.1) 标签保持不变，不含本次升级修复。不要把不同版本的指南和源码混用。

Agent 负责核实宿主、项目范围、同源技能完整性与真实加载；未知能力须报告，不猜目录或命令。这不是独立安装器或全客户端兼容保证。安装不等于项目采用，也不授权改写项目规约、业务实现或发布。

## 已装旧版？先预览升级

v3.1 是破坏性变更：旧 `sop-startup`、`sop-requirements` 和模板/额外规则已退役；复制覆盖不会自动清除旧文件，更换插件路径也不会移除项目中的旧引用。先让 Agent 按[升级说明](docs/upgrading.md)检查实际来源、定制与活动入口，预览完整切换后再授权。不自动删除旧内容，也不保留旧规则作为兼容壳；任务历史、失败次数和未完成验证原样保留。

本版补充了按需升级指引、确定性回归和显式真实 CLI 测试入口。人工审批的 v2 定制样本已核对文件切换、历史与备份完整，并实际调用新版 `sop` 和 `sop-verification`；退役两入口不可调用。重跑、恢复及迁移后任务仍未实测，正常宿主后台动作也不在工具包控制内。这不是自动迁移器或跨宿主无缝兼容保证，详见[验证记录](docs/testing.md)。

## Claude Code 本地插件（可选）

在业务项目目录启动，指定已审阅的完整工具包副本的绝对路径：

```sh
claude --plugin-dir "/absolute/path/to/ai-coding-sop-kit"
```

进入后可调用：

```text
/ai-coding-sop-kit:sop
请先阅读项目，说明结构和现有测试，不修改文件。
```

这只为当前会话加载，不是全局安装。项目技能形态使用实际发现的 `/sop`，不带插件命名空间，也没有插件启动 hook；不要未经确认同时启用两套入口。不提供 marketplace 安装。

需要已有且可用的 Claude Code；获取远端源码另需 Git。使用技能不需要额外 Python、模型 SDK 或 API Key，客户端费用按其自身账户计费。

## 五个技能

| 技能 | 何时使用 |
| --- | --- |
| `sop` | 接入流程、明确目标/授权/责任、选择当前所需技能 |
| `sop-design` | 需要调研、方案选择、关键取舍与契约设计；关键歧义先澄清 |
| `sop-execution` | 已授权实施，分析完整影响范围并实现、自测 |
| `sop-verification` | 核对预期依据、实际执行证据，准备交叉验收与交付 |
| `sop-recovery` | 失败止损、必要验证受阻、恢复或交接 |

按真实任务触发，不要求依次走完。清晰低风险任务不必补设计文件；实现者可以在同一会话运行测试，换 AI 会话不能替代验收责任人。文档按需要复用现有位置，不强制模板、数量或目录。

## 底线与边界

- 开工有目标、边界、验收条件、实施授权与验收责任；能查明的事实先查，关键歧义交人裁决。
- 先识别必要调用方、数据和测试，再求最小改动；保留他人改动，不顺手扩展功能或架构。
- 预期有独立依据，验证实际执行；必要证据缺失只能报告部分完成，最终验收保留非实现者交叉检查和责任人决定。
- 同一问题连续两次修复失败停止自动重试，换 Agent 或会话不清零。缺少验证条件时记录影响、恢复动作、责任人与复查时点，不自动变成完成。

技能是模型指引，不是权限沙箱或自动审批。启动 hook 只读导航，不修改业务文件、不跑项目测试。加载、采用、实施、提交和发布是不同授权。
