# AI Coding SOP Kit

将 AI Coding 工程实践 SOP 转换为跨工具的开发规约与工作流。目标是让新 Agent 能读取规则、恢复项目基线、识别停止条件，并提供可核对的交付证据。

**这是纯文档规约包，不是执行框架、安全沙箱或自动门禁。** 不包含脚本、任务 JSON、项目历史、业务代码、全局配置或安装程序。

## 内容

```text
AGENTS.md                       常驻规约
.agents/skills/sop/SKILL.md      唯一工作流正文
 docs/sop/original.md            原 SOP v1.0（保留原文）
 docs/sop/workflow.md            阶段协议与失败路由
 docs/sop/templates.md           按需使用的记录模板
 docs/sop/adapters/              工具接入说明
```

## 接入自己的项目

1. 先检查项目已有规约与同名文件。将本包的 `docs/sop/`、`.agents/skills/sop/` 放进目标项目；AGENTS.md 不存在时使用本包版本，已存在时合并规则和入口，**不得直接覆盖**。
2. 如有同名 Skill 或文档冲突，先确认如何合并或改名，并同步引用。不修改客户端全局配置，不复制本仓库的 `.git/` 到项目。
3. 阅读对应工具说明，确认工作区根目录和规约加载方式。无需为未知客户端猜测快捷命令或创建兼容层。
4. 首次发送下面的入口指令，并核对实际读取/工具记录：

```text
请读取项目根目录 AGENTS.md，并按其中要求读取 SOP 工作流和阶段协议。
根据已确认需求和当前任务判断阶段；没有必要信息时先澄清。
说明允许的动作、需要裁决的问题和未验证项，不擅自开始业务实现。
```

之后直接提出任务即可，不要求每次手动调用 Skill。客户端不能自动读取 AGENTS.md 时显式提醒；加载入口不代表自动加载所有引用文件，后续读取仍由 Agent 执行。

## 工具说明

## 项目需要自行提供什么

本包不规定语言、框架、部署方式或测试工具。项目需明确真实需求、验收标准、实施授权、相关接口，以及实际验证入口。优先用已有测试、构建、lint、类型检查、实测与 CI；缺失时提出最小方案，不擅自加依赖或伪造通过。

需求与任务记录使用项目已有位置；没有约定时可建立 `docs/requirements/`、`docs/tasks/`，模板见 [templates.md](docs/sop/templates.md)。这些记录在真实任务发生时生成，不随本包附带。不要对简单任务机械凑文档或数量。

## 验收与边界

检查 Agent 是否在歧义时澄清、越界时请求授权、未验证时如实报告、连续失败后停手、换会话时恢复基线。核对工具日志、diff 和真实 runner，不只看 Agent 说“已遵守”。

本包不能自动阻止工具调用，也不证明业务标准正确。需要硬门禁时，在项目中另行设计并审阅检查脚本、CI、权限和审批；不将它们作为使用本包的默认依赖。

## 分享与维护

可以把规约包作为独立仓库或压缩包交给接入者，接入者仍需审阅规则和冲突。维护一份核心，各工具只保留接入说明；换模型、换工具不重写已确认需求，不清零失败记录。

原文保留在 [original.md](docs/sop/original.md)。执行层明确区分草案与真实批准、停止修复与批准交付、独立评审与同源 AI 背书，并按任务风险校准经验阈值。
