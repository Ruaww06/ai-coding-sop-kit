# AI Coding SOP Kit

面向需求驱动全栈开发的 Agent 工程技能：从需求文档出发，经需求与设计评审，组织跨层实施，以真实证据交付，让问题回到正确层级解决。

**SOP 内容 v4.0 · 包版本 4.0.0-beta.1 · Beta 预发布版。** 六个按需技能，保留 v3 的五个入口并新增需求技能。本版已通过 42 项确定性检查，尚无 v4 真实宿主加载或业务行为验收；建议先在低风险项目试用。

> 任务可以小，判断不能空；记录可以合并，责任不能消失。


跟随公开 main 的通用入口：

```text
请获取并遵循 https://raw.githubusercontent.com/Ruaww06/ai-coding-sop-kit/refs/heads/main/INSTALL.md，识别当前宿主，将 AI Coding SOP Kit 安装到当前项目；先核对实际版本，遇到冲突询问，不覆盖项目定制，也不自动开始业务开发。
```

main 会随开发变化，需要可复现来源时使用 [v4.0.0-beta.1 标签](https://github.com/Ruaww06/ai-coding-sop-kit/tree/v4.0.0-beta.1)。指南与源码必须来自同一完整来源；本地修改副本还应报告未提交差异，HEAD 不足以标识其内容。Agent 核实宿主、范围、资源完整性和真实加载，不猜目录或命令。安装不等于项目采用、业务授权或发布。

## 六个技能与两条路径

| 技能 | 职责 |
| --- | --- |
| `sop` | 接入、核对依据与授权、选择当前需要的步骤 |
| `sop-requirements` | 澄清需求、调查必要事实、组织非起草者需求评审 |
| `sop-design` | 调研、选择最简单完整方案、检验跨层行为与关键设计 |
| `sop-execution` | 安排依赖与进度，在授权范围内实施和自测 |
| `sop-verification` | 核对独立预期、实际证据、端到端场景与交叉验收 |
| `sop-recovery` | 所有阶段的归因、裁决、依据更新、增量重做及阻塞恢复 |

**向前：** 澄清与调研 → 需求评审 → 设计评审 → 计划与实施 → 验证与验收。

**回流：** 证据与归因 → 对应负责人裁决 → 写回依据 → 重审受影响部分 → 增量实施与验证 → 确认关闭。

这不是每次必须依次调用六个技能。小任务引用有效的已有评审与设计，只处理变化部分；文档写满不等于已经评审。完整功能检查用户场景如何贯穿交互、接口、业务和数据，前后端各自单测通过不能替代端到端行为验证。原型先明确问题、授权与退出条件，不能未经评审验证直接作为正式交付。

## 已装旧版？保留入口，核对内容

- **从 v3 更新：** 现有五技能名、`common.md` / `upgrade.md` 路径、项目技能和本地插件形态保留，新增 `sop-requirements`。已有有效评审和批准继续按原范围使用；缺少评审的部分补审，不全量重写，也不自动补成已通过。
- **从 v2 更新：** `sop-requirements` 虽然同名，内容已重写，不能只凭名称判断兼容；旧 `sop-startup`、额外规则和模板副本仍退役。真实填写的需求、计划和问题是项目资产，不随资源清理删除。
- **从 v1 或混合来源更新：** 先查项目引用链、内嵌规则、定制和真实加载来源，预览完整切换后获授权。不能靠覆盖目录或只换插件路径消除旧活动规则。

所有升级保留失败次数、挂起项、许可证和历史；升级不是业务批准、补测通过或项目验收。详见[升级说明](docs/upgrading.md)和[安装协议](INSTALL.md)。本包不提供自动迁移器，也不承诺未知定制或内部路径无缝兼容。

## Claude Code 本地插件（可选）

在业务项目目录使用完整、已审阅源码的绝对路径：

```sh
claude --plugin-dir "/absolute/path/to/ai-coding-sop-kit"
```

进入后使用：

```text
/ai-coding-sop-kit:sop
请先阅读项目，说明结构、现有需求和测试，不修改文件。
```

项目技能形态使用宿主实际发现的 `/sop`，没有插件命名空间或启动 hook；不未经确认并用两套入口。不提供 marketplace 安装，也不修改全局配置。需要已有且可用的宿主；使用技能不需要额外 Python、模型 SDK 或 API Key，费用按宿主自身账户计费。

## 底线与证据边界

- 需求和关键设计经过非起草者评审，人负责目标、取舍和风险；AI 可辅助，不能伪造批准。高风险事项需要有相应能力的人审查。
- 先识别完整影响范围，再求最小；复用优先，不削弱校验、安全、数据保护、错误处理和无障碍。
- 验证实际执行，预期独立；必要证据缺失只报部分完成，最终验收保留非实现者交叉检查和责任人决定。
- 同一问题连续两次修复失败停止自动重试；同一设计前提反复失效也需重审。换会话不清零。
- 阻塞明确缺失、影响、恢复动作、责任人与复查时点，项目结束逐项清算，不静默转为完成。

技能是指引，不是权限沙箱或审批系统。hook 只读导航，不修改业务、不运行测试、不证明安全。确定性测试、宿主加载和实际行为分别报告；旧版有限观察不作为 v4 通过结论。
