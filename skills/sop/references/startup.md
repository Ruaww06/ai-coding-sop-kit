# 项目启动与接入

新项目第一天建立规约骨架：六段 AGENTS.md（第 0—5 段）、`docs/forbidden.md`、`docs/glossary.md` 和项目检查入口 `scripts/check.sh`。检查入口须包含适用的 lint、类型检查、测试及新增路径扫描；不存在的能力明确记录，不放置永远返回成功的占位脚本。

先完成规约准备再进入需求阶段。本包分发技能、资源和简短启动引导；安装仅使技能可用，不授权项目初始化。缺少的项目文件和脚本先列清单，在获得相应授权后补齐，不因安装插件自动执行业务脚本。

AGENTS.md 第 0 段填写所需交互模式、采用本 SOP 的确认来源及项目规则入口。不并行第二套冲突的 AI 工作流。中途接入先盘点在制品、已有规约与未验收项，再经人确认切换；冲突部分暂停，不强删原项目约定。

启动时盘点历史临时产物，清理前查看内容并取得删除授权。Agent 可控的临时产物只写仓库内被 gitignore 的 `tmp/` 或派发单指定目录，不读写 `/tmp`、主目录 `~` 或系统临时目录作为工作区。客户端自身缓存不代表 Agent 已控制其位置，不能虚报已清理或已拦截。
