# 阶段与出口

| 阶段 | 主要产物 | 出口与停止条件 |
| --- | --- | --- |
| 需求 | 澄清清单、需求文档、验收标准、调研记录 | DoR 为 B；歧义未裁决、记录未核验不进入设计 |
| 设计 | 架构说明、接口契约、数据模型、不变量、ADR | Design Freeze 为 B；契约、数据模型、ADR 缺一不进入执行 |
| 执行 | 开发计划、派发单、代码、测试、进展索引 | 项目检查全绿、diff 在白名单、依赖锁符合授权、归因已记录，均为 B |
| 测试验收 | 测试报告、Known Issues、验收结论 | 本地可验 B、外部实测 H、强度 S；不由实现者自批验收 |

### 需求与调研

按范围、边界、异常、约束、非功能五个决策轴逐项填澄清清单；无歧义也写明依据，空清单不算完成。歧义由人回答，AI 建议和默认值不当作答案。纯机械小改动只有人显式判定 S 并记入派发单后才可跳过澄清。

需求包含：一句话目标、范围及至少三条非范围、至少三条 Given/When/Then 可断言验收、数字约束、依赖与假设、至少三条异常/边界、提出人与不同的评审人。无适用数字时说明待裁决项，不编造指标凑数。必须真机/实测的验收逐项标明；验收变更返回需求裁决，测试不得自行增删。

开工前必查清单只登记一份，设计前和动手前引用同一记录：外部候选方案至少两个、成熟实现的存在性/活跃度/可借鉴点、与项目现状的差异；内部检索负向知识。链接来自本次实际检索/抓取，附核验日期及人核验来源；未查内容写“未调研”，不凭记忆补链接。检索过期知识时先核验，不能直接作为当前依据。

DoR 与 DoD 逐项对应：验收→用例及人确认的预期，非范围→diff，数字约束→实测，依赖→真实集成，异常→反向用例，调研→ADR 候选方案及差异。DoR 不挂起；对应实测 DoD 仅可 B/H，不可 S。

### 设计冻结与派发

前置数据所有权和生命周期、跨模块契约及错误语义/幂等、权限、一致性、外部选型与退出路径、非功能数值、回滚策略。每条约束给失败场景。非功能目标的定义属 B，物理环境缺失时其实际测量才可申请 H；替身的实现细节可按档位 S，退出路径不可省。

契约、数据模型和 ADR 可引用已有且仍有效的文档，不为小改动重复生成；适用性及无需变更的依据写入任务。没有接口或持久化模型时在设计记录明确其不存在及理由，交人评审，不以空文件假装完成。ADR 至少记录本次关键取舍或沿用决策的依据及被否决方案。

冻结后、首个派发前建立开发计划，任务拆为单一可验证结果：输入/输出/边界/验收可用一段话说明；已有文件改动不超过五个（新增另列）；接口可见；预计不超过一次往返。超出先拆分。硬依赖的前序任务先于后续任务执行，负责人不同于验收人。

计划是任务档位和状态的唯一登记处；派发单回指任务编号，不重复登记档位。任务卡须附范围白名单、验收锚点、实施授权、真实检查命令、参考实现、知识检索关键词和命中条目（无命中也明确）。缺确认时先复述并等待；已确认同一目标/范围不反复索批。
