# 失败路由、知识与交接

- L0：已有规约明确、实现未守 → 补上下文并局部修。
- L1：工具/依赖/环境 → 记环境证据，不改产品标准。
- L2：契约/模型无法满足需求 → DCR 写推翻的假设、影响、验证，更新契约/ADR 后重新派发；设计负责人裁决。
- L3：业务定义空白/矛盾 → 需求澄清卡，需求方与负责人裁决，不猜。

同一处两轮修复失败、同一处返工至少两次或任务超过三个失败点时停止自动重试，记录复现、尝试、归因与待裁决者；换 Agent 不清零。安全、主流程阻塞、数据损坏立即停并升级，不能当成普通 Known Issues 交付许可。并发/事务/幂等、权限/密钥/支付/删除、公共契约/schema、性能敏感路径须人工裁决；没有必要授权不实施。

L2 默认每日两个固定裁决窗口，48 小时内裁决；负责人兼任多职可放宽到周窗口。L3 本周窗口裁决。阻塞/安全问题即时处理。同模块七天内第三次 L2 或同一 DCR 引发回归超过两次，停工转三十分钟人工设计评审。

负向知识沿用启动记录中确认的唯一知识库位置（项目既有目录或任务平台），读取和检索也从该入口进行；尚无约定时可建议 `docs/knowledge/`，由人确认位置并取得写入授权，不另建第二套。条目包含来源、验证日期、验证过的最小用例、失效条件；其余记录只链接。归因和 DCR 推翻的假设须写入并进入检索池才算沉淀完成，不能只留会话。超过六个月未命中条目标 deprecated 并移出检索池。外部知识同样带四字段；固定采集来源与节奏仍待项目确定，不编造已完成。

重新派发使用已确认基线与版本指纹 + 增量变更，明确未列部分维持原样；先复述变化，获真实确认后继续。交接包保留任务、需求/设计、真实授权、失败次数、HOLD 链接与旧误区，不附凭证或未脱敏会话。

交付说明实际文件及理由、逐条验收证据、未验证项、Known Issues、文档更新或无需更新的依据，并给符合项目提交规范的拆分与信息草案。提交、推送、部署、发布、删除和全局配置操作不因 SOP 自动获授权。
