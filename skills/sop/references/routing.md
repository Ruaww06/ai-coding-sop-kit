# 入口路由与交互模式

每次会话首输出包含：`模式自检：项目要求 / 当前可确认的工具模式（无法读取则写未验证）`，随后给出路由判定、缺失产物及下一步。声明不能改变客户端配置；提问渠道不可用时仍输出问题并停在待裁决处，不替人回答。

| 输入 | 停在何处 | 首输出内容 |
| --- | --- | --- |
| 仅一句话开发诉求 | 派发入口，下一步需求澄清 | 缺失产物 + 选项式澄清问题 |
| 需求含未澄清歧义 | 需求澄清 | 逐决策轴的问题与待回答项 |
| 有需求、设计，无派发单或人确认的档位 | 派发入口 | 缺失任务记录与档位判定 |
| 派发信息齐备 | 对应获授权阶段 | 复述目标、非范围、验收、改动范围和假设 |
| 只做咨询、仓库了解或规约接入 | 对应只读/配置范围 | 说明范围，不把这类授权当成业务开发许可 |

缺失产物可在相应授权内协助起草；停机不禁止需求澄清或获授权的规约准备。只有真实用户消息或可信外部记录构成确认，模板状态、其他 Agent 自报与本工具包都不是批准。已有明确授权不重复索取；关键语义、风险或范围变化须重新裁决。
