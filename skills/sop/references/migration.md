# 旧项目识别与授权迁移

本协议供安装 Agent 与 startup 使用，不是自动迁移器。安装技能、宿主加载、项目规则切换是三个独立结果。为防止“新技能已装好但旧规则仍生效”，先只读识别，再决定是否迁移；hook 不扫描或改写项目。

## 1. 只读识别

- 在已确认的目标项目范围内，读取适用的 `AGENTS.md`、`CLAUDE.md` 和它们明确引用的其他规则入口；检查 `docs/sop/`、`.agents/skills/sop/SKILL.md` 及当前宿主的技能目标。同一项目可能在多个宿主下各有一份副本：只读查看其他已知宿主的项目级位置（如 `.claude/skills/`、`.dsh/skills/` 及已核实的客户端目录），仅用于识别重复副本与版本漂移，不把其他宿主目录当作当前宿主的活动入口。嵌套项目按本次授权范围检查，不扫描其他 workspace、插件缓存、用户级技能或整个主目录。
- 检查路径是否为符号链接或越出项目；遇到这类路径只报告，不跟随读写。无权限、无法枚举或未读到的入口写“未验证”，不能当作不存在。
- 对照同一来源 checkout 的内容和可用的 `v1.0` 基线，结合版本声明、正文与引用关系判断来源。只有路径或一个“SOP”字样不是版本证据；来源不明、被改写或 v1/v2 混合时列事实与疑点，不猜版本、不强行转换。基线不可用时不擅自扩展网络操作，报告比对限制。
- v1 的典型组合是项目入口引用 `docs/sop/workflow.md`、`docs/sop/templates.md` 和 `.agents/skills/sop/SKILL.md`，旧 Skill 又按项目根读取这些正文。旧版允许合并项目规约，匹配部分原文也不证明整文件可替换。

| 实际证据 | 分流 |
| --- | --- |
| 检查范围内未见旧入口，且无未验证项 | 新装或当前版更新；安装不自动采用 SOP |
| 有 v1 或来源不明的旧正文/旧引用，或新技能与旧活动入口在本宿主内并存 | 旧版或混合候选；进入下面的迁移预览，不能仅按当前阶段开始开发 |
| 本宿主未见旧入口，其他宿主位置有同一工具包的副本 | 多副本候选：内容与本次来源一致时报同源副本；不一致、不完整或项目规则仍引用该宿主路径时报版本或入口漂移；列位置、差异与引用，询问活动接入和同步方式，不改其他副本，也不据此判项目已迁移 |
| 仅有同名目录、未知版本、检查不全或实质冲突 | 状态未确认；列缺项并询问，不把项目判为已迁移 |
| 新版入口与资源已核验，采用引用一致，旧副本仅作非活动归档 | 已切换候选；复核当前文件后无需重复改写或重复索取同一有效授权 |

## 2. 预览与授权

仅安装、更新技能或“看看项目”的授权不包含迁移业务规约。即使用户说“升级 SOP”，未明确的冲突和删除范围仍需裁决；已有明确且适用的逐项授权不重复询问。

1. 盘点旧入口、用户定制、规约副本，以及进行中任务、需求、计划、真实授权、失败次数、HOLD 和 Known Issues。历史缺失写未知，不能清零或补造批准、验证与完成状态。
2. 先确认新版完整技能组及所需资源可用，按宿主实际能力核验：支持原生技能时，核实实际加载内容来自所选新版，而非仅看到同名 `sop`；旧 Skill 抢占同名入口或加载来源不明时不算成功，其他宿主下的副本或读取其他宿主路径也不构成本宿主加载成功的证据。应支持发现但尚未生效时报告“加载待验证”，不得撤下唯一可用旧入口或宣称切换完成。没有原生发现机制、只支持显式读文件的客户端，则实际读取已核实的新版入口和所需阶段资源，确认项目采用的读取路径稳定可用后，报告“显式读取已核验，原生发现不适用”；仅文件存在不算完成，也不能用此分支绕过宿主原生发现失败。
3. 列逐文件差异：原引用、拟采用的新入口、保留的定制、拟停用的重复入口、旧规约主体的逐条保留/替换/退役建议、保持不动的记录、未解决项与恢复办法。不能只换链接：根 AGENTS/CLAUDE 或被引用正文中的旧执行规则仍可能生效；与 v2 冲突的条款列明差异并交人裁决，不能统称 CUSTOM 保留，也不能借升级擅自删除。新入口必须使用已实际发现的宿主名称或已核实的项目相对路径，不写 staging、私人绝对路径或易变插件缓存路径。
4. 与人确认采用方式、负责人、记录位置及这份差异的授权。拒绝或暂缓时不改业务文件，保留旧流程，报告“技能已安装（如属实），项目未迁移”；不能诱导忽略旧规则或并行执行冲突流程。

## 3. 执行与中断恢复

- 仅在授权文件范围内合并入口与仍有效的项目定制；不整文件替换 `AGENTS.md`/`CLAUDE.md`，不复制工具包维护者规约，不重写需求、计划、KI 或历史状态。检查能力和 v2 前置条件的缺项另列，不伪造就绪。
- 不只改 AGENTS 的链接：宿主仍会发现的旧 `.agents/skills/sop/SKILL.md` 也是活动入口，需按已批准方案停用；不能靠“请忽略旧技能”冒充切换。若宿主停用方式未知，停在待确认状态。
- 删除、移动旧目录或文件需明确的路径与相应授权。其他宿主下的副本不在本次授权范围：不同步、不移动、不删除，除非用户明确要求并另列路径与范围。默认保留不再被发现/引用的旧正文作非活动归档；旧目录内的定制与项目记录不随技能清理。保留 `docs/sop/LICENSE` 等适用许可证，不用批量删除处理引用冲突。
- 操作前重新比较当前文件与预览基线；出现新的用户改动、授权范围变化或未知入口时停止受影响部分并重新预览。不能拿旧差异覆盖新内容。
- 沿用项目现有记录位置，在文档授权内记录来源 commit、逐项结果、保留项、未验证项及下一步，不建立任务数据库。仅安装时不创建采用或迁移记录。
- 中断后先读取当前文件、记录与有效授权，重新识别实际活动入口和差异；已完成且一致的步骤不重写，只继续剩余已授权项。缺少授权证据时先询问，不根据“上次应该同意过”推断。
- 失败时报告实际改动与剩余入口，暂停受影响的业务执行。不擅自删除新文件、回滚用户工作或重置整个仓库；恢复也须比较当前差异并在授权内进行。

## 4. 切换验收与报告

重新读取所有受影响入口及其引用，检查新版资源可读、原生加载或无原生发现时的显式读取已按第 2 节核验、旧活动 Skill 已停用、旧规约主体冲突已按真实裁决处理、没有冲突的 v1/v2 双路由、项目定制和任务历史仍保留。仅归档但仍被宿主发现或被规则要求读取的旧文件不算停用。核查范围及未读部分必须明示。

分别报告：识别证据与范围、技能文件安装、宿主加载或显式读取及不适用项、其他宿主副本的位置与同源或漂移状态（含规则是否仍引用、待确认的同步项）、项目迁移（未授权 / 未开始 / 部分完成 / 已核验）、实际变更、保留内容、未解决项及下一步。只有授权项完成且上述检查有证据时，才报告“项目迁移已核验”；这不代表业务测试、v2 启动齐备或最终验收通过。重复执行无差异时报告无需变更，不凭上次成功记录跳过核验。
