# 安装、更新与移除

SOP v4.0 / 包 `4.0.0-beta.1` 为 **Beta 预发布版**。固定来源使用 `v4.0.0-beta.1` 标签的指南与完整源码；main 是移动开发入口。实际来源、版本、commit 和本地改动分别核对，不能拼装不同版本。确定性检查通过不代表真实安装、原生加载或模型行为已验收。

六技能为 `sop`、`sop-requirements`、`sop-design`、`sop-execution`、`sop-verification`、`sop-recovery`。保留原五入口、common/upgrade 相对资源路径和项目技能/本地插件形态。`sop-startup` 仍退役；v2 同名需求技能必须比较正文，不能原样沿用。

## 一句话交给 Agent

在目标项目中发送：

```text
请获取并遵循 https://raw.githubusercontent.com/Ruaww06/ai-coding-sop-kit/refs/tags/v4.0.0-beta.1/INSTALL.md，使用同标签完整源码，将 AI Coding SOP Kit 安装或升级到当前项目；核实宿主与版本，遇到冲突先预览询问，保留项目定制、评审、授权、失败和未完成验证记录，不自动开始业务开发。
```

Agent 按同一来源的 [INSTALL.md](../INSTALL.md)确认宿主、项目根、权限和接入方式。公开 main 通用入口见 [README](../README.md)，不能把其未来内容当作固定标签。已有本地源码也可提供稳定绝对路径，核对真实内容和本地改动，不因路径名称推断版本。

Claude Code 项目技能机制为 `.claude/skills/`，DeepSeek Harness 为 `.dsh/skills/`；项目根与当前 profile 先核实，其他宿主不猜目录。完整六技能组同层，正文与资源单源。项目技能不带插件命名空间和启动 hook；机制资料不构成跨宿主验收。

## 安装边界

安装前比较同名内容、额外文件和已知活动入口；未知、修改过或混合来源先预览。来源含意外活动技能、退役规则或版本不一致时停止报告，不静默过滤。检查引用与实际内容，不以固定文件数证明完整。

项目技能只安装完整技能及许可证，不复制维护者 AGENTS、Git、测试、CI、插件清单或 hook；工具包 LICENSE 可置于 `sop/LICENSE`，不替换项目许可证。不改全局配置或权限，不自动同步其他宿主副本。安装、采用、业务实施、提交合并和发布各有授权。

## Claude Code 本地插件（可选）

在业务项目目录使用已有可用的 Claude Code：

```sh
claude --plugin-dir "/absolute/path/to/ai-coding-sop-kit"
```

这是用户选择插件形态后的启动方式，不是安装 Agent 自动启动另一模型的授权。使用已审阅完整源码的稳定路径，空格路径保留引号。

插件使用 `/ai-coding-sop-kit:sop`，项目技能使用宿主实际发现的 `/sop`；不未经确认并用两个入口，不提供 marketplace 安装。hook 只读导航，不初始化项目、不运行测试、不批准操作，也不保证模型遵循。

## 核验、更新与移除

安装后对照同源比较全部技能、资源、额外文件和许可证，实际调用入口并核对基目录，确认新增需求技能可被发现。文件存在、原生发现、真实调用与正确行为是不同证据；未观察加载就报告待验证，一次调用不证明全组行为。必要时由用户开启新会话，不绕过权限或自动调用付费模型。

已有安装先读[升级说明](upgrading.md)和随技能分发的[升级指引](../skills/sop/references/upgrade.md)：

1. 只读盘点来源、活动入口及引用链、内嵌规则、定制和业务记录，不能因新目标路径不同而漏查旧入口。
2. 预览完整保留、替换、停用方案与验证/恢复。Git/插件副本优先用新完整来源，不 reset 修改过的副本；复制安装不靠整目录覆盖消除旧文件，暂存在发现路径外。
3. 获完整切换授权后执行；关键冲突在覆盖共享正文前裁决，不自动删除旧项。先核实新来源可用；无法隔离验证时明确可恢复方案，保留旧入口于发现范围外，新加载仍须实测。
4. 分开核验文件、宿主加载和项目规则切换：旧入口不再活动、引用无断链、冲突已解决，定制/许可证/历史保留。只换插件路径不能证明这些条件。
5. 中断后重读现状和有效授权；新差异修订预览，不覆盖新改动、不自动回退、不清零。内容已一致则不重写。

### 已有项目采用 v4

查真实需求与设计评审证据；有效且未变化的部分复用，缺评审的部分补审，不自动追认也不全量重做。需求和关键设计不能只由起草者自评通过，最终验收保留非实现者交叉检查，AI 一致不替代责任人。

复用项目任务记录，关联依赖、负责人、验收、验证和状态，保持阻塞、回流与下一步责任可见。问题保留证据、交对应责任人裁决、写回依据，重审受影响部分、实施并重验后确认关闭。不强制造文件套装或另建数据库。

升级保留批准的实际范围、失败次数、HOLD、未决问题和未完成验证，不能变成业务启动或验收许可。真实填写的需求、计划、授权和失败证据是项目资产，不因模板退役删除。

移除前列明本次目录和本地修改并获授权，不删除整个技能根或项目记录。停止向新会话传插件参数即停止该会话形态加载，不自动撤销项目改动，也不证明当前缓存已更新。

本版未实测真实安装、加载、模型行为或完整升级链路。确定性结果与历史观察分别见[验证说明](testing.md)，外部依据见[设计说明](design.md)。
