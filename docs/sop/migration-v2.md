# 迁移到 v2 技能包

## 版本和形态

SOP 内容版本为 v2.0，当前插件分发版本为 `2.0.0-beta.1`；旧基线在 Git 标签 `v1.0`。内容版本与分发版本不代表同一承诺。

v2 从复制整套规约的文档包改为 `skills/` 单源技能 + Claude Code 插件清单 + 只读启动导航。没有工具包专用 CLI、任务数据库、模型 API、自动审批或业务检查器。项目仍需真实验证入口。

## 从 v1 文档包或中间 v2 文档副本迁移

Agent 的单源操作协议见 [旧项目识别与授权迁移](../../skills/sop/references/migration.md)，它随整组技能分发，由安装入口和 `sop-startup` 共用；以下是使用者概览，不是另一套迁移器。通用[一句话安装入口](../../INSTALL.md)先识别宿主与能力、只读检测旧版线索，再在明确授权后迁移；已有新版能力时也可对入口说“检查旧 SOP 并预览迁移，先不要改文件”。旧版检测、定制合并和授权仍由 Agent 执行，不提供透明兼容层或自动保证。

仅安装不会改业务规约。若拒绝迁移、无法确认版本或新版加载未验证，保留旧入口并报告项目未迁移；不要同时按冲突的新旧流程执行业务。迁移中断后重读实际状态与有效授权，重跑只处理剩余差异。完整切换须核验规则引用及宿主会发现的旧 Skill，而非仅确认新文件存在。

1. 在目标项目盘点已有规约、旧 Skill、副本、进行中任务、真实授权、失败次数、HOLD 与 Known Issues。保留用户改动，缺历史不猜零，不倒填批准和测试。
2. 在独立位置获取并审阅新版，按 [安装说明](../installation.md) 本地加载或由宿主安装；不要把工具包根 AGENTS.md 覆盖给业务项目，它已改为维护者规约。
3. 确认入口技能与阶段资源实际可读。插件安装只是能力可用，不自动决定项目采用或改写旧项目记录。
4. 与人确认采用方式、负责人、交互模式、记录位置及 [执行与适配边界](../../skills/sop/references/boundaries.md)。不同时执行冲突流程；保留仍有效的项目定制。
5. 旧 `docs/sop/` 和 `.agents/skills/sop/` 可能继续指向旧正文。先预览差异并确认新版入口可用，再取得授权逐项更新/撤销旧引用；不自动删除目录或覆盖用户扩写内容。新版不再分发旧兼容入口，改用完整 `skills/` 技能组。
6. 需求、计划、KI 和知识留在项目；迁移引用，不搬进插件缓存。补齐 v2 的 DoR、冻结设计、人确认档位和 H 留痕时以真实来源为准，不把已有任务一律改成完成。
7. 项目检查能力单独核验；需要新增脚本、依赖、权限或执行操作时另按授权处理。文档/技能安装不证明门禁齐备。

## 更新和撤销

宿主管理插件升级与卸载；手动副本通过固定 tag/commit 获取。插件自身变化与目标项目的采用声明、定制规约是分开的：卸载不删除项目记录，更新也不覆盖它们。多客户端保留同一技能正文，但分别核验发现、调用与上下文恢复能力。

## 规则与模板位置

[阶段协议](workflow.md)及[模板](templates.md)已改为索引，唯一执行正文在 `skills/sop/references/` 与 `assets/`。每个阶段技能只引用所需内容，避免全文常驻和规则双登记。执行边界集中在 [适配说明](../../skills/sop/references/boundaries.md)，不在升级文档重复数值。

尚未验证的能力及发布前检查见 [测试说明](../testing.md)。文件齐备或结构检查不能替代实际加载、触发和业务验收。
