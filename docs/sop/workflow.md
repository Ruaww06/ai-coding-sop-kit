# 阶段协议

## 恢复基线

从用户指定任务、已确认需求、设计和真实确认来源恢复当前阶段，不在通用规约中保存项目状态。无已确认需求先澄清；多个进行中任务先询问。模板或 Agent 自报不是用户批准。

## 阶段与出口

| 阶段 | 允许动作 | 出口证据 | 停止条件 |
| --- | --- | --- | --- |
| 需求 | 真实场景澄清、起草范围与验收 | 可判定标准及真实确认来源 | 核心语义空白/矛盾 |
| 设计 | 核实依赖、必要契约/数据/风险设计 | 可证伪约束及必要裁决 | 关键取舍未确认 |
| 执行 | 授权范围内实现和测试 | 代码、任务记录、实际验证 | 越界、未裁决风险、L2/L3 |
| 验证 | runner、实测、独立评审准备 | 逐条证据及未验证项 | 环境阻塞、熔断、缺外部真值 |
| 待验收 | 提交材料、用户真实操作 | 独立评审与用户验收记录 | 不由实现者自批 |

明确且已授权的低风险任务直接继续，不每次要求重复批准。授权起草文档不等于授权业务实现；停止自动修复不等于批准交付。

## 按风险校准

原 SOP 的条数、文件数、时限和往返数是经验起点，不机械凑指标。小任务可省不适用产物并说明原因；关键业务、接口、数据与安全约束不省。探索原型可降低测试要求，但仍报告未验证与风险，不宣称生产就绪。

必须前置影响他人的数据、契约、权限、一致性、回滚决定；局部内部结构可延后。不要让用户预先决定所有技术细节，Agent 应提出方案及可判定取舍。

## 任务与验证

使用项目既有任务平台、文档位置及版本基线。修改前列出允许范围和任务前已有改动，不覆盖他人工作；新增文件也说明范围。任何扩展由真实授权决定，不依赖 Agent 自填状态。

优先复用项目已有测试、构建、类型检查、lint、契约验证及真实环境实测。无适用入口时提出最小验证方案，新增依赖/脚本按项目授权处理。本包不提供或强制一种检查器、数据格式或自动化平台。

验收证据对应实际代码版本。测试覆盖率只用于查漏，不是正确性证明；两个模型意见一致或代码相似也不是证据。未执行、失败、环境阻塞分别说明，不将其转成通过。

## 失败路由

- L0：已有规则明确，实现未遵守 → 补上下文并局部修。
- L1：工具、依赖或环境阻塞 → 保存环境证据，不改产品标准。
- L2：契约/模型无法满足需求 → 写明推翻的假设、影响和验证方式，等设计裁决。
- L3：业务定义空白/矛盾 → 提交澄清，不猜。

同一问题两轮修复失败或任务超过三个失败点时停止自动重试。记录复现、尝试、归因、待裁决者和下一步。安全/数据完整性问题即时升级；Known Issues 不构成自动豁免。阈值调整须明确记录，不靠换会话重置。

## 交接与控制边界

新 Agent 读取真实需求、必要契约、当前任务、失败记录和旧误区，复述不变基线后继续。不要分享凭证或未脱敏会话。

AGENTS.md 与工作流是模型指引，不自动强制执行。验证标准正确性、关键风险和最终验收需要人；程序可检查的项使用项目独立 runner。需要硬门禁时另行审阅权限、检查脚本、CI 和审批，核实绕过路径及失败行为，不把工具专属配置写入通用核心。
