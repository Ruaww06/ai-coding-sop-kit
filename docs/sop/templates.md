# 按需记录模板

使用项目已有记录位置和格式。下面是内容骨架，不强制建立全部文件。真实任务发生时填写；未定/未验证项如实标记，不能以模板状态代替批准。

## 需求卡

```markdown
# 需求：<目标>
- 状态：草案 / 已确认（附真实确认来源）
- 用户与真实使用场景：
- 一句话目标：
- 范围 / 非范围：
- AC-01：Given ... When ... Then ...（可直接断言）
- 其他适用验收：
- 约束：性能/成本等有要求时给数字，不凭空编阈值
- 异常与边界：
- 依赖与核实来源：
- 用户事实 / Agent 建议 / 未定项：
- 确认依据：没有则写未确认
```

## 任务卡

```markdown
# 任务：<单一可验证结果>
- 需求与验收引用：
- 目标 / 非范围：
- 已确认设计、接口与同类实现：
- 允许改动范围（含新增文件）：
- 开始基线与已有改动：
- 实施授权依据：
- 适用验证入口、环境与预期来源：
- 风险 / 未定事项：
```

## 失败与设计变更

```markdown
- 问题和最小复现：
- 实际证据：
- L0 / L1 / L2 / L3 与理由：
- 尝试方案、修复轮次和结果：
- 推翻的设计假设 / 缺失业务定义（适用时）：
- 影响范围：
- 候选处理及代价：
- 是否停止、待谁裁决、真实裁决来源：
- 下一步允许动作及验证方式：
```

## 交付报告

```markdown
| 验收项 | 独立预期来源 | 用例/实测证据及版本 | 通过/失败/未验证 |
| --- | --- | --- | --- |

- 文件和修改理由：
- 实际命令或操作、结果与对应代码版本：
- 未验证项及原因：
- Known Issues、影响及是否阻塞：
- 独立评审：待进行 / 结论及真实来源
- 用户验收：待进行 / 结论及真实来源
```

## 干净交接包

已确认需求及来源 + 代码基线 + 当前任务 + 相关契约 + 最小复现 + 已尝试方案/失败次数 + 旧误区警告 + 当前阻塞 + 下一步允许动作。不附凭证、无关历史或未经脱敏的会话。
