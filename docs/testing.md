# 测试与兼容性

本工具包处于 beta 阶段。确定性测试验证打包、资源引用和脚本行为；模型场景测试只描述有限环境中的观察，不保证模型每次遵守流程。

## 确定性测试

在工具包根目录运行：

```sh
python3 -m unittest discover -s tests -v
```

测试框架仅使用 Python 标准库。hook 和 CI 脚本用例需要 POSIX sh；提交范围回归需要 Git，无 Git 时该项会明确跳过。测试不调用模型、不安装插件，也不修改全局配置。

测试覆盖：

- 插件元数据、版本一致性、七个技能的格式，以及已移除的旧入口和市场清单不再分发。
- 本地链接、代码围栏、整组技能搬移后的资源引用。
- 启动脚本在中文、空格路径下的重复执行、缺失资源和只读行为。
- 执行阶段停机规则引用、H 待裁决与批准分离、既有知识库入口约定。
- 临时检出路径下的 Markdown 校验。
- 干净工作树中已提交的空白错误，以及 push、PR 和新分支的差异范围。
- 安装入口、入口技能与 startup 链接到同一份随技能分发的迁移协议；旧入口识别先于复制，授权、定制/历史保护、中断恢复和分别报告的静态契约。
- 九个合成旧项目场景（含两个跨宿主副本场景：已有副本只报告不修改，规则引用其他宿主路径时按漂移列差异并询问）的格式与路径安全，以及真实只读 hook 重复执行后文件保持不变。此项只验证 hook 不改旧项目，不执行也不模拟 Agent 迁移。

现有套件包含 18 项测试，已在 macOS 本地通过；原有 14 项曾通过 Linux/macOS CI，新增回归尚未验证远端 CI，以对应提交的 [GitHub Actions](https://github.com/Ruaww06/ai-coding-sop-kit/actions) 结果为准。静态文字断言只防止协议漏接或保护条款意外丢失，不证明 Agent 会遵守。

安装了 Claude Code 时，可校验插件清单：

```sh
claude plugin validate .claude-plugin/plugin.json --strict
```

清单验证不等于技能已加载，也不等于行为正确。部分客户端版本的目录验证会返回空的内容列表，因此不将该结果作为技能发现的证据。

## 模型场景测试摘要

已测试环境：macOS、Claude Code 2.1.287；跨宿主副本另有 DSH 桌面版有限尝试（两次隔离子会话与一次 headless CLI 会话，见下文）。以下是有限场景观察；原始运行记录不是分发内容。

| 范围 | 已观察结果 | 限制 |
| --- | --- | --- |
| 本地加载与启动 | 发现七个命名空间技能，启动导航可见 | 不代表 marketplace 安装成功 |
| 只读了解与需求澄清 | 保持只读，提出需求问题 | 单次场景，不是稳定性统计 |
| 证据不足的交付声明 | 未把模型共识作为测试通过证据 | 不替代项目业务验收 |
| 小范围修复 | 先复现失败，再修复并通过测试；独立检查范围与预期 | 合成小任务，不代表所有编码任务 |
| 挂起与失败恢复 | 区分申请和批准，保留失败计数，按证据处理回收 | 合成场景，不是真机或长期挂起验证 |
| 原生 resume | 同一会话恢复历史，并重新读取任务记录 | 不包含 clear／compact |
| 显式命名空间入口 | 已输入入口并观察到后续规则读取 | 未独立核验宿主的命令展开记录 |

除下述有限迁移场景外，最新规则尚未重跑此前全部模型场景。上述行为观察对应各次测试时的插件快照，不应扩大为最新版本的完整行为保证。

### v1 迁移有限实测

在同一 macOS / Claude Code 环境中，以 Opus 5.5 加载本地插件快照，对独立合成项目执行五次有界调用。旧规约、Skill、workflow 与模板取自固定 `v1.0` 基线，另加项目定制与任务历史哨兵；未复制完整原始材料，缺失的旧引用由 Agent 如实报告。

- **只读预览**：实际调用入口和 startup，并读取迁移协议；识别活动旧引用、根规约主体差异及定制/任务历史。前后文件摘要一致，未宣称迁移完成。文件操作工具虽在工具集中，未证明其写权限当时可用，不能将零改动推广为可写环境中的边界保证。
- **授权迁移**：实际尝试编辑入口，但文档写入被权限策略拒绝；未改用其他工具绕过，报告未迁移。此项验证到拒绝后的停止行为，**未验证成功合并或停用旧入口**。
- **合成中断检查点**：恢复了已切换入口和新增定制，未重写/回滚该入口；剩余编辑与归档操作受权限阻塞，报告部分完成。检查点由测试执行者构造，不是真实崩溃或原生 resume；未证明成功续迁移。

- **授权切换成功**：在不含客户端敏感祖先目录的新建样本中，保留 restricted、逐文件写入授权和精确归档命令，实际加载入口与 startup、读取迁移协议后，合并三份项目规则并退役旧规则主体的冲突采用，将旧 Skill 移出活动目录，新增迁移记录。独立检查确认改动只在授权路径，归档 Skill 与迁移前 SHA256 一致，旧活动 Skill 路径已不存在；API/依赖/生产配置/人工发布定制保留。实际工具记录无权限拒绝、无额外模型或子 Agent 调用，未用权限跳过模式。

- **完成后重跑**：在已成功切换的同一合成项目中新建模型上下文，仍提供有限文档写工具权限，但本轮只授权检查。实际重读规则、归档、任务/KI 及新版资源后报告无需变更；工具记录无写入调用、无重复授权要求、无工具错误，项目与插件前后摘要一致。没有因为历史副本仍在而重复迁移或删除；仅为单次幂等观察，不代表统计可靠性。

五次调用后业务代码、许可证、旧正文、定制补充、任务/失败/HOLD/KI 哨兵均保持不变，插件与源码快照未被模型改动。该成功结果仅覆盖一个带定制的合成 v1 项目在 Claude Code 本地插件形态中的明确授权切换及一次重跑，不是通用迁移可靠性保证；未证明可写环境下仅安装时绝不越权。成功续迁移仍未执行。原始工具日志和合成项目仅保留本地，不随工具包分发。

测试工作区应使用项目批准的专用临时目录，避开客户端受保护的配置目录及其祖先。权限拒绝必须作为环境阻塞报告，不能把零改动当迁移通过，也不能为测试关闭权限保护。

### 通用安装协议的有限尝试

在未预装技能、未传入插件的独立 Claude Code 合成仓库中，让 Agent 读取完整本地候选指南与来源清单。已观察到正确识别宿主、项目根及 `.claude/skills/` 接入方式，并在整组复制前检查旧版与来源。一次审批受阻的场景停在复制之前，如实报告未安装、加载待验证，项目与来源前后摘要一致。

成功安装场景保留 restricted，由测试父进程通过 stdio 逐次审批精确的目录创建、七技能复制和许可证复制，不使用权限跳过模式。Agent 自行选择 Claude Code 项目技能接入，读取候选指南、项目规约和迁移规则，检查目标后复制；没有预装技能或传入插件。独立检查确认新增的 30 个技能/资源/许可证文件与候选逐字节一致，只有 `.claude/skills/` 内新增文件，原项目规约、代码、许可证、Git 文件和候选来源不变，没有安装插件清单或启动 hook。

安装会话未发现新技能，正确报告“文件安装完成、加载待验证”，没有以显式读取冒充原生调用。随后在普通 CLI 的新会话进行仅初始化、无用户任务、无模型调用或工具执行的发现检查，原生列出七个技能且均标为 project，文件摘要保持不变。restricted 会话的同类初始化未列出项目技能；测试模式的发现限制与普通会话应分别记录。

另一次普通 CLI 新会话的只读模型调用实际执行了 `Skill(sop)`：工具结果确认调用成功，宿主返回技能正文及当前项目 `.claude/skills/sop` 基目录；随后实际读取安装位置的 `references/common.md`、`references/migration.md` 并枚举七个同层技能。未传 `--plugin-dir`，未使用插件命名空间，只有 Skill/Read/Glob 调用且无工具错误，项目前后摘要不变。该轮不带 restricted，以允许项目技能发现；仅提供只读工具，不能用来证明具有写工具时也始终守住范围。

上述证据覆盖**本地候选来源 → Agent 文件安装 → 普通新会话原生发现 → 项目技能真实调用与资源读取**；不是远端 URL 获取全链路验收。用户级同名技能/插件优先级未完整核验；完整性及符号链接部分采用父测试执行者的独立证据，不能据此保证未知宿主兼容。

### 跨宿主副本的有限尝试

在同一 macOS 上，用 DSH 桌面版 0.2.0-rc.2 的两次隔离上下文子会话执行安装（共享父会话的文件系统与沙箱，未启动独立 CLI 进程）。两次都使用专用临时 fixture（gitignored，未提交、未分发）：fixture 先放一份真实的 `.claude/skills/` 前次安装副本（七个技能加 `sop/LICENSE`，与来源逐字节一致），再让 Agent 按安装入口把技能装到 `<projectRoot>/.dsh/skills/`。安装前记录 fixture、工具包源目录与工作区顶层快照，事后由独立流程核对。

- **已有副本、规约不写死路径**：Agent 识别 DSH 与 `.dsh/skills/` 接入，用 `diff -rq` 与哈希确认 `.claude/skills/` 是同源当前版副本，按多副本候选报告；未把它当作本宿主入口、安装冲突或加载证据，也未改动、同步或删除。实际只在 `.dsh/skills/` 新增 30 个文件；`AGENTS.md`、任务记录和 `.claude/skills/` 哈希不变。
- **已有副本、规约写死其他宿主路径**：Agent 识别 `AGENTS.md` 指向 `.claude/skills/sop/SKILL.md` 为入口漂移，指出其中 `references/common.md` 相对项目根会悬空，保留 `CUSTOM` 与失败/任务历史，未改写规约、未删除或归档其他副本，停在授权前并列出待确认项；同样只新增 `.dsh/skills/` 30 个文件。
- **加载（隔离子会话）**：两次都未观察到原生加载。DSH 的项目根是最近含 `.git` 的祖先，否则用会话 cwd；fixture 未成为项目根时 `.dsh/skills/` 不在扫描范围内，`skill` 工具返回未知技能。Agent 报告“文件安装完成、加载待验证”，未用显式读取冒充原生加载，也未改配置或启动新模型进程。
- **加载（fixture 内 headless 会话）**：随后在该 fixture 目录内直接启动一次 headless CLI 会话（`dsh --profile headless`，cwd 即 fixture），任务只要求调用 `skill` 工具加载 `sop` 并报告基目录与正文首行。会话记录显示本次唯一工具调用为 `skill`；工具结果 `skill_content name="sop"` 的基目录为 `<fixture>/.dsh/skills/sop`，正文首行为 `# SOP 入口`，进程退出 0。同目录同时存在 `.claude/skills/` 副本，宿主加载的是自己的 `.dsh/skills/`。运行后 fixture 62 个文件哈希与工具包源目录均未变。该会话启动需写入工作区外的 profile 与会话目录，使用了一次性扩大文件权限授权；这不是稳定性或行为验收。

独立核对确认新增文件只在 `.dsh/skills/`，fixture 其余文件哈希、工具包源目录与 git 状态、工作区顶层均未变；安装来源为工作树（HEAD `df2ccff` 加未提交改动），事后源文件哈希一致。局限：每场景一次、共享沙箱；原生加载只观察到一次 headless 会话，未覆盖升级时的副本同步、用户级或插件优先级、跨宿主稳定性，也未做业务行为验收。原始 fixture 与记录保留在本地临时目录，不随工具包分发。

## 尚未验证

- 原生 clear／compact 后的导航和任务恢复。
- marketplace 安装、更新、卸载及缓存重载。
- Windows 环境下的脚本兼容性。
- Kimi 等其他客户端的原生技能发现；DSH 只有一次 headless 会话的原生发现与加载观察。
- 公开 URL 获取的通用安装全链路、未知宿主识别与显式读取回退；已有 Claude Code 本地候选的文件安装、普通新会话原生发现及项目技能真实调用证据，不等于全客户端端到端验收。
- v1 → v2 成功续迁移、其他定制形态与跨客户端切换；跨宿主副本识别与一次 DSH 原生加载已观察到（见上），仍不构成端到端或稳定性证据。已有单个合成项目的 Claude Code 本地插件授权切换和重跑证据，不等于 Harness 一句话安装/迁移端到端通过。
- 真实设备、周窗口、长期挂起、超限升级和复杂项目的持续表现。

权限限制、前后文件检查和模型遵守规则是不同证据。只读环境中没有改动，不能证明可写环境中也守范围；文件哈希不变不能证明期间没有短暂改动。技能及 hook 不提供不可绕过的安全隔离。

## 贡献行为测试

使用独立的合成项目，不使用真实客户数据或凭证。记录环境、输入、实际工具调用、结果及局限；预期应来自需求或独立规格。涉及付费模型、文件写入或扩大权限时，应先取得相应授权。

公开报告只保留必要的环境、方法、结果和局限。不要提交私人对话、批准原话、费用记录、会话标识、个人路径、账户信息或未脱敏日志。`tests/behavior-cases.json` 与 `tests/migration-cases.json` 是场景定义，不是已执行结果。

迁移场景的 `files` 是最小合成输入，不是完整 v1 发布副本；包含仅安装、定制预览、非本工具包同名目录、新旧活动入口并存、其他宿主已有副本（同源与漂移）、中断后新增修改、已迁移重跑和逐项授权执行。运行时先在专用项目写入对应输入，提供真实宿主技能发现/加载环境。授权执行场景还需测试执行者提供可信的逐项批准和当前基线，不能把 fixture 或 Agent 自述当批准。分别观察文件差异、工具调用、是否改动其他宿主副本、是否停用旧活动入口、定制和历史保留及报告；记录未覆盖能力。离线测试只验证这些输入与 hook，不声称完成迁移。
