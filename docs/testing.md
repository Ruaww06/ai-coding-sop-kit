# 验证方法与局限

SOP v4.0 / 包 `4.0.0-beta.1` 为 Beta 预发布版。确定性检查只验证分发结构、文本契约和脚本；模型行为、安装成功与业务验收是不同证据。本页不将旧版结果沿用为新版通过。

## v4 发布前本地检查

- 修改前 v3 基线 33 项 unittest 通过。新增 v4 文本契约先运行出现预期的 5 项失败和 1 项缺技能错误，随后补齐实现；这只确认检查能发现文本缺失，不是行为测试。
- 当前完整 unittest **42 项通过、无跳过、退出码 0**，包括六技能元数据与相对资源、只读 hook、v4 评审/进度/反馈文本契约及真实历史 Git 文件回归。
- 新增历史回归核对 `v3.1.0-beta.2` 固定提交：原五入口及 common/upgrade 路径保留，完整新组新增需求技能且链接有效，合成项目需求/任务/规则记录不变，同内容重复复制无内容差异。另核对 v2 同名需求技能正文不同且旧支持文件不能被默认为兼容。
- `claude plugin validate ai-coding-sop-kit --strict` 通过；有 `ICON_MISSING` 非阻断目录警告和 marketplace 安装建议。本包不提供 marketplace，不能据此声称目录安全/政策审核通过。
- `sh -n hooks/session-start.sh` 与 `git diff --check` 通过；hook 的实际只读、重复运行、中文/空格路径和缺资源用例由 unittest 执行。
- 真实行为观察器按每次冻结来源清单核对技能，不写死五技能；合成回归覆盖五/六技能及多余入口拒绝，旧样本仍按其自身基线判断。不运行真实模型。
- 20 条业务行为规格仍为 `not-run`，包括未评审需求/设计、依赖与进度、反馈写回、设计反复失效和旧评审复用。本次未调用付费模型、未安装到业务项目、未验证 v4 原生发现或加载、未执行新旧真实项目切换。以有限证据发布 Beta，不宣称这些未验证项目通过。

这些检查支持分发和文件层面的兼容性，不证明 Agent 正确作出裁决或执行升级。真实评审、业务效果、跨宿主兼容及人的最终接受仍须分别确认。以下带 v3 标记的观察是历史资料，不是 v4 的通过结论。

## 确定性检查

在仓库根目录运行：

```sh
python3 -m unittest discover -s tests -v
claude plugin validate . --strict
```

第一项使用 Python 标准库，脚本用例需要 POSIX sh，提交差异回归需要 Git；缺能力须明确跳过，不算通过。第二项仅在已安装 Claude Code 时执行，不为测试安装客户端。均不应调用付费模型、安装插件或改用户配置。

应检查：

- 当前技能元数据、包版本及文档一致性；技能组完整且资源引用可搬移。
- Markdown 本地链接与代码围栏，不把临时目录误当分发内容。
- hook 的中文/空格路径、重复执行、缺资源报告和只读行为；不将脚本输出当作真实宿主注入成功。
- v4.0 的需求/设计评审、依赖进度、全阶段反馈，以及授权、独立依据、真实验证、非实现者验收和阻塞恢复；不以旧术语或模板数量代替机制。
- CI 对提交范围的空白检查，包括 push、PR、新分支及强推情形；干净工作树不等于已提交差异无错误。

## v3 beta.2 历史升级检查覆盖

本候选新增 2 项升级文本契约检查、5 项真实发布文件回归、2 项独立行为验收器回归、2 项人工终端启动保护及 2 项续验门槛回归，总计 33 项。历史回归从本地 Git 对象提取 `v1.0`、`v2.0.0-beta.1`、`v3.1.0-beta.1` 的实际 blob，核对固定提交，在仓库隔离临时目录执行文件复制和引用解析，不运行旧脚本、不联网、不操作业务项目：

- v2 七技能被新版加法覆盖后，两个退役技能和旧模板/规则仍存在；不是一次完整升级。
- 保留两旧技能而只提供新支持文件时，真实资源引用断开。
- 按 v1 复制范围构造项目后，向新目录装技能不会改掉 AGENTS 旧引用、旧正文或 `.agents` 入口；项目追加定制、许可证和失败/验证记录仍在。
- 以 v1 文档复制清单复制 v2 内容，会让兼容重定向和索引缺少根 `skills/` 目标。
- beta.1 五技能组原有链接有效，但缺少升级指引；完整新组复制后资源齐备，重复同内容复制不产生内容差异。

这些测试复现文件系统事实与危险前提，**没有自建模拟迁移器，也没有证明 Agent 能正确合并、获批、停用入口或恢复中断**。JSON 定义的 11 个 Agent 升级场景仍为 `not-run`；hook 在这些 fixture 上实际只读运行，不等于场景本身已执行。下述两条独立真实 CLI 观察使用另外冻结的输入，不回填其他场景为通过。

本地标签或 Git 不可用时，真实历史回归会明确跳过，不自动联网获取；只有跳过数为零才可声称本页对应的全部历史测试执行过。CI 拉取完整历史及标签；源码下载包内没有 Git 对象，不能将跳过历史测试当作已通过。

保护的任务记录、应用、项目许可证、API 兼容性定制与候选来源均保持；没有可观察的写入调用。前后哈希不证明绝无瞬时变化，也不证明受限模式行为可代表正常可写环境。成功切换、迁移后任务、重复升级、拒绝路径与中断恢复均尚未实测，**端到端升级闭环未通过**。

人工入口要求真实终端、manual 逐项审批、受控移动/删除、全新未改动样本和独立日志。交互模式没有美元硬上限，预算需人工监控；非 TTY 启动会在模型调用前拒绝。该人工路径已执行，独立文件检查确认活动五技能与冻结来源一致、资源链接有效；旧七技能的 28 个文件及原 AGENTS 备份与基线一致，定制、应用、项目许可证和任务历史保留，未见授权范围外文件变化。

交互运行正常退出，文件切换经过宿主人工审批路径；未执行拒绝场景，不能算拒绝路径通过。审批与原始运行记录留在本地，不作为公开完整输入审计。

升级后活动项目技能为五个；原会话内新版 `sop` 和 `sop-verification` 原生调用成功，`sop-startup` 与 `sop-requirements` 已不可调用。来源与内容通过宿主加载信息及独立文件核对交叉确认，不用显式 Read 代替原生调用。另三个新入口未逐一原生调用，全局/plugin 同名优先级未专项验证。

**本次带定制 v2 样本的项目级文件切换与上述原生加载检查通过。** 这不是跨宿主兼容保证，也不代替人的最终接受、应用或真机验证。重复升级、迁移后小任务、中断恢复与拒绝路径仍未实测，完整端到端场景集尚未闭环。

正常宿主存在环境副作用：调试日志显示插件后台更新并从远端获取仓库、用户级缓存及宿主状态写入、自动标题和 away-summary 模型请求。未见任务模型主动使用网络工具、委派工具或发起额外模型命令；不能把这限缩为整个进程“零网络、无额外请求或无用户级写入”。本次不是离线或完全隔离运行，宿主后台动作与工具包/任务模型行为分别报告，后续测试前应明确该环境边界；不得为得到干净结论而隐去它们。该观察未据此放宽权限或自动追加测试调用。

### 续验状态

重复升级和新会话文档任务的两阶段入口已准备，但发布前未执行；不将准备、静态检查或已有升级结果算作这两项通过。中断恢复、拒绝路径和跨宿主覆盖也保持未验证。本 Beta 按上述有限证据发布供试用，不宣称完整端到端升级链路通过。

## 真实宿主与行为检查

在获授权的合成项目中分别观察：来源获取 → 内容一致性 → 宿主发现 → 真实调用和资源来源 → 任务行为。每一步独立报告；不能用显式读取掩盖原生发现失败，不能用一句“已加载”证明来源正确。

有代表性的任务包括：

- 只读了解项目，不因缺少模板而初始化或索取业务批准。
- 已有有效目标和授权的简单任务直接实施，不重复审批；关键歧义则交人裁决。
- 新能力先查已有实现与适用证据，选最简单的完整方案，不凑候选数量或强造设计文件。
- 修复先复现，影响范围内实施和自测，保留他人改动；同会话测试不冒充最终验收。
- 没运行检查或缺少必要条件时只报未验证/部分完成；本地失败不包装成外部阻塞。
- 连续两次修复失败停止自动重试，恢复或交接不清零；交叉验收不能由另一个 AI 会话替代责任人。
- 安装/更新遇到同名定制先询问，保护旧项目记录及其他宿主副本，不自动删除旧入口。

每项记录实际环境与版本、输入、工具调用、相关代码基线、结果和局限。预期来自需求、独立规格或不变量，不从实现反推。涉及付费模型、写测试工作区或扩大权限，先获相应授权；权限拒绝后不能通过其他工具或外部会话绕过。

## 尚未验证与证据边界

- 本候选的真实模型任务行为、稳定性和业务验收效果。
- 公开 URL 获取到本版的安装全链路、移除及更多旧安装形态；本地 v2 定制样本以外的升级成功路径。
- Claude Code 项目技能除本次 v2 定制样本的刷新发现及两个原生调用外的覆盖；插件形态、全局同名优先级及 resume/clear/compact 恢复。
- Harness、Kimi 等其他宿主的本候选原生加载和业务行为；目录文档支持不等于兼容验收。
- Windows 和跨宿主缓存/优先级行为。

旧版曾有有限本地加载和安装观察，但方法与技能内容已变，不能沿用为 v3.1 通过。前后文件哈希不变不能证明期间从未短暂改动；只读权限下无写入不能证明可写环境仍守范围。hook 和技能不提供不可绕过的隔离。

## 贡献证据

使用合成输入，不放真实客户数据或凭证。公开报告只保留必要的环境、方法、结果和局限，不提交私人对话、审批原话、账户、个人路径、会话标识或未脱敏日志。静态测试、模型场景与最终业务验收分别报告，缺少必要证据只能报告部分完成。
