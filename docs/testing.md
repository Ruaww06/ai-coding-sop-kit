# 验证方法与局限

SOP v3.1 / 包 `3.1.0-beta.1` 为 Beta 测试版。确定性检查只验证分发结构和脚本；模型行为、安装成功与业务验收是不同证据。本页不将旧版结果沿用为新版通过。

## 确定性检查

在仓库根目录运行：

```sh
python3 -m unittest discover -s tests -v
claude plugin validate . --strict
```

第一项使用 Python 标准库，脚本用例需要 POSIX sh，提交差异回归需要 Git；缺能力须明确跳过，不算通过。第二项仅在已安装 Claude Code 时执行，不为测试安装客户端。均不应调用付费模型、安装插件或改用户配置。

应检查：

- 当前技能元数据、包版本及文档一致性；技能组完整且资源引用可搬移。
- Markdown 本地链接与代码围栏，不把临时目录误当分发内容。
- hook 的中文/空格路径、重复执行、缺资源报告和只读行为；不将脚本输出当作真实宿主注入成功。
- v3.1 的授权、独立依据、实际验证、非实现者验收、失败止损和阻塞边界，不以旧版术语或固定模板数量代替要求。
- CI 对提交范围的空白检查，包括 push、PR、新分支及强推情形；干净工作树不等于已提交差异无错误。

## 真实宿主与行为检查

在获授权的合成项目中分别观察：来源获取 → 内容一致性 → 宿主发现 → 真实调用和资源来源 → 任务行为。每一步独立报告；不能用显式读取掩盖原生发现失败，不能用一句“已加载”证明来源正确。

有代表性的任务包括：

- 只读了解项目，不因缺少模板而初始化或索取业务批准。
- 已有有效目标和授权的简单任务直接实施，不重复审批；关键歧义则交人裁决。
- 新能力先查已有实现与适用证据，选最简单的完整方案，不凑候选数量或强造设计文件。
- 修复先复现，影响范围内实施和自测，保留他人改动；同会话测试不冒充最终验收。
- 没运行检查或缺少必要条件时只报未验证/部分完成；本地失败不包装成外部阻塞。
- 连续两次修复失败停止自动重试，恢复或交接不清零；交叉验收不能由另一个 AI 会话替代责任人。
- 安装/更新遇到同名定制先询问，保护旧项目记录及其他宿主副本，不自动删除旧入口。

每项记录实际环境与版本、输入、工具调用、相关代码基线、结果和局限。预期来自需求、独立规格或不变量，不从实现反推。涉及付费模型、写测试工作区或扩大权限，先获相应授权；权限拒绝后不能通过其他工具或外部会话绕过。

## 尚未验证与证据边界

- 本候选的真实模型任务行为、稳定性和业务验收效果。
- 公开 URL 获取到本版的安装全链路、更新/移除和旧项目切换。
- Claude Code 项目技能及插件在本候选上的真实发现、调用、resume/clear/compact 恢复。
- Harness、Kimi 等其他宿主的本候选原生加载和业务行为；目录文档支持不等于兼容验收。
- Windows 和跨宿主缓存/优先级行为。

旧版曾有有限本地加载和安装观察，但方法与技能内容已变，不能沿用为 v3.1 通过。前后文件哈希不变不能证明期间从未短暂改动；只读权限下无写入不能证明可写环境仍守范围。hook 和技能不提供不可绕过的隔离。

## 贡献证据

使用合成输入，不放真实客户数据或凭证。公开报告只保留必要的环境、方法、结果和局限，不提交私人对话、审批原话、账户、个人路径、会话标识或未脱敏日志。静态测试、模型场景与最终业务验收分别报告，缺少必要证据只能报告部分完成。
