# SOP 工作流

## 入口

读取项目根目录 `AGENTS.md`、`docs/sop/workflow.md` 和 `docs/sop/templates.md`。路径按项目根解析。没有原生 Skill 时直接读取本正文，不要求特定调用命令。

读取用户指定的任务及已确认需求；存在多个候选时询问，不静默选取。恢复真实授权与当前阶段，模板状态不构成批准。只执行本阶段允许动作。

## 需求

- 从真实场景整理目标、范围/非范围、可断言验收、约束、异常和未定事项。
- 区分用户事实、Agent 建议与未确认内容。关键语义空白时提问，不开始业务实现。
- 可以提出验收草案，但不能自己确认；不为模板凑数字或让用户代做所有技术判断。

## 设计

- 前置数据所有权、跨模块接口及错误语义、权限边界、真实依赖、量级和回滚。
- 向用户解释必要取舍；没有硬约束时提出最小方案，不默默替业务裁决。
- 按影响写必要契约/不变量/ADR，局部细节可延后。轻量任务不机械生成全套文档。

## 执行

- 复述目标、验收、范围与假设，读取相关代码、接口和已有测试，优先复用。
- 使用项目已有任务记录和版本基线。明确允许改动的文件/模块，不越界或顺手重构。
- bug 先复现，重构先锁行为；实现与验证短回路交替。
- 验收标准、依赖、公共契约或风险变化先取得相应确认。不重复请求已明确的同一授权。

## 验证和归因

使用项目已有检查入口及真实 runner。缺验证基础时提出最小可行方案，不擅自增加工具，不把缺失当通过。

- 预期来自需求、规格、外部真值或不变量；不照抄实现写断言。
- 记录实际命令/实测、结果、对应版本和未验证项。代码再变后重验。
- L0 局部修，L1 记环境，L2 回设计，L3 回需求。
- 同一问题两轮失败或超过三个失败点时停手，保存接手材料。不得改标准或换会话掩盖失败。
- 同源 AI 意见不代替业务 oracle；独立评审需读取真实基线和 diff。

## 交付

按模板提供逐条验收证据、文件及理由、未验证项、Known Issues 和待验收项。自测、独立评审、用户验收分开，不自批通过。换会话保留失败次数和旧误区。

例：用户只说“做一个知识管理工具”时先澄清，不自选框架写功能；已确认的局部 bug 则先复现、限定范围、修复并验证。

详细依据按需查阅 `docs/sop/original.md`。本工作流是指引，不是审批系统、自动 runner 或安全隔离。
